# 013 – XLSX adapter and row pipeline (Bank of England base rate)

## Goal
Excel workbooks (including hidden sheets, several sheets per source) can be read and cleaned by the declarative row pipeline, proven on the Bank of England base rate workbook.

## Acceptance criteria (each must be checkable)
- [ ] xlsx config per spec: `sheet` / `sheet_index` / `sheets: [..]` / `sheets: {except: [..]}`, `start_row`, `end_row`, `header`, `columns` by letter, `use_cached_values`. Hidden sheets are readable; formulas are **never evaluated** (cached values only); unknown sheet gives an error naming available sheets. Each emitted record gets `_ctx.sheet` and `_source: {sheet,row}`.
- [ ] Pipeline steps implemented and unit-tested in isolation: `skip_rows`, `drop_if_empty`, `section` (with `default`), `fill_down` (with `reset_on: section`), `normalize` (`trim lower upper to_int to_string collapse_ws to_number`), `unpivot` (list or map columns, empty cells dropped), `split` (named groups, `optional`), `strip`. Steps apply in order; step errors are `RowError`s, never panics.
- [ ] `context:` values from the source config appear as `_ctx.<name>` on every record and are usable in `natural_key` as `@ctx.<name>`.
- [ ] Safety: workbook size, sheet/row counts and decompressed size are limited (default 100 MB file / 2M rows), exceeding them is a clear error; a crafted zip bomb test is rejected; no network access, macros or external links are followed.

- [ ] A second golden test reads `testdata/ashe/t20-7a-trimmed.xlsx` with the sheet/skip/split/strip pipeline from `docs/examples/ashe-t20-annual-pay.group.yaml` (no unpivot, no zip: location is the xlsx itself, archive ignored in this test): sheets `All` and `Male Full-Time` each give **217** rows; first row has empty `age_band`; the row for `18-21 ALL OCCUPATIONS` has `age_band=18-21`, `soc_name=ALL OCCUPATIONS`, empty `soc_code`; a two-digit SOC row has `soc_code` without the apostrophe.
- [ ] (added by the orchestrator, lesson from task 011) `kind: xlsx` is registered end to end: config validation accepts it (`sources apply` no longer says "supported: csv"), and the adapter registry used by `importer run` (cmd/importer registration line only, plus its test) includes it, so an xlsx source can be applied and run from the CLI.

- Decision, cell values: read with excelize `Rows` + `RawCellValue`, so every cell is a **string exactly as stored**: text as text, a number as its saved literal (`13.8438`, `1E-3`, no display-format rounding), a boolean as `1`/`0`, an error cell as its literal (`#N/A`), an empty or missing cell as `""`. Formulas are never evaluated (`CalcCellValue` is never called): a formula cell yields its cached value, or `""` if none was saved. Typed values appear only where `normalize` makes them: `to_int` gives int64, `to_number` gives int64 or float64. The streaming API gives no per-cell type or style, so **date-formatted cells arrive as their Excel serial number text and are not converted to dates** (contradicts the mapping-spec sentence; excelize `GetCellType` would load whole sheets into memory, rejected because of the size limits).
- Decision, `normalize` on mixed types: text transforms (`trim lower upper collapse_ws`) leave non-strings alone. `to_int`: text or number holding a whole number (`" 1694 "`, `1694.0`, `1e3`, int64, whole float) gives int64; empty/blank text is unchanged; anything else (`abc`, `x`, `1.5`, hex, `inf`, `NaN`, `1_000`, >= 1e15, bool) is a `RowError` naming the column. `to_number`: plain decimal text gives int64 (integer literal that fits) else float64; markers (`x`, `..`, `1,234`, hex, `Inf`, empty) are left as they are; literals with more than 15 significant digits that do not fit int64 stay text (no silent precision loss); numbers stay. `to_string`: number/bool to text, nil stays nil. A column absent from the row is skipped.
- Decision, limits (`XLSXLimits`, adapter-level; zero = default): workbook file **100 MiB** (fetch `MaxBytes` is lowered to it, `ErrTooLarge`), **2,000,000 rows** walked over all selected sheets (skipped, blank and gap rows count; `ErrXLSXTooManyRows`), **256 sheets**, **1 GiB** total decompressed, **10,000** zip entries, **16 MiB** of text in one row (`ErrXLSXRowTooLarge`, fatal like csv). Before excelize reads anything, `checkZip` rejects a declared entry/total over the limit and then really inflates each entry through a limit of its declared size + 1 (a lying header is caught; a bomb is never expanded past the limit). excelize also gets `UnzipSizeLimit` = limit and `UnzipXMLSizeLimit` = min(limit, 16 MiB). Invalid, garbled, truncated or OLE-encrypted workbooks give `ErrXLSXBadArchive`; panics inside excelize are recovered and returned as errors (Open and Next). No network, macros (`vbaProject` never read) or external links are followed. The bomb test uses small configured limits (20 MB of spaces vs 1 MiB), not the 1 GiB default.
- Decision, sheets and rows: hidden sheets are read like any other and are marked `(hidden)` in the "available sheets" list of the unknown-sheet error. `sheet_index` is 0-based. `sheets: {except}` keeps workbook order; an unknown name in `sheet`/`sheets`/`except` is an error naming the available sheets; excluding everything is an error. Rows whose configured columns are all empty are skipped silently before the pipeline (spacer rows); rows outside `start_row`..`end_row` are skipped; `Record.Position` and `_source.row` are the real 1-based row number; `RowError.Raw` is `Sheet!row: | cell | cell`. Merged cells: only the top-left cell holds a value (covered cells are empty, so `fill_down` can carry it); `GetMergeCells` is not used. Columns not in `columns` are not read. With `header: true` and no `columns` the header row (`header_row`, default 1) gives the names (an empty header cell means the column is ignored; duplicate or `_`-prefixed names are an error); `start_row` defaults to the row after the header; `header` defaults to **true** (like csv). `use_cached_values: false` is rejected.
- Decision, pipeline/context/key: `table`, `context` and `xlsx` are top-level source keys; `table`/`context` on a csv source are rejected at validation (not supported yet) rather than silently ignored; `csv` on xlsx and `xlsx` on csv likewise. `context:` scalars are stored as strings; every record gets `_ctx` = context + `sheet` + section variables (a section variable overrides a context one; `sheet` is reserved) and `_source: {sheet,row}`. `natural_key` entries are a field name, a context/section variable name (falls back to `_ctx`, as the BoE example's `series_name`), or `@ctx.<name>`; `@meta.` is rejected. **An empty part is allowed** (BoE events without a day, ASHE "All employees"); only a key with every part empty is a `RowError`. Keys and step columns are validated statically in config (columns known) or per sheet at Open from the header (same code) with field-path errors such as `table[3].normalize.year[1]`. Section/fill_down state is per sheet; headings are trimmed; `section.match` is tested only against text; `fill_down reset_on: section` forgets values at each heading.
